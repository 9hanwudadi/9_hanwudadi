# 基于 STC8H8K64U 的 51 四足机器人

本仓库用于四足机器人项目的硬件资料、底层驱动、应用功能、接口文档和整合测试。

项目原则：**稳定优先、接口清楚、问题可定位、模块可以独立测试。**

## 项目结构

```text
hardware/                 原理图、PCB、接线与硬件说明
firmware/
  drivers/                GPIO、Timer、PWM、UART、舵机及传感器驱动
  app/                    动作、模式与机器人状态控制
docs/
  interfaces/             各模块对外接口文档
  hardware-resources.md   引脚、定时器、串口、中断等资源登记
tests/                    模块测试与整合测试说明
```

## 分支约定

- `main`：可演示、可验收的稳定版本。
- `develop`：日常开发和模块整合。
- `feature/功能名`：从 `develop` 创建，例如 `feature/servo-driver`。
- `fix/问题名`：修复问题，例如 `fix/servo-jitter`。

建议通过 Pull Request 把功能分支合并到 `develop`；联调稳定后再合并到 `main`。

## 分工方向

- 硬件 / PCB：最小系统、电源、舵机接口、下载串口、制板焊接与硬件排错。
- 软件驱动层：GPIO、Timer、PWM、UART、舵机、延时和外设驱动。
- 软件应用层：运动动作、模式切换与状态控制。
- 项目整合：工程结构、资源协调、代码合并、联调与最终测试。

应用层不要直接操作寄存器，优先调用驱动层提供的接口。

## 模块提交要求

每个模块至少包含：

1. 功能说明与对外接口文档。
2. 参数、返回值、初始化顺序和硬件资源说明。
3. 正常情况与异常情况测试。
4. 清晰的提交信息，说明修改内容和接口变化。

真实问题、排查过程和个人理解必须由本人记录到手写项目错题本中。

## 命名约定

- 宏：`SERVO_MAX_ANGLE`
- 函数：`Servo_SetAngle()`、`UART_SendString()`
- 全局变量：`g_robot_mode`
- 文件：`servo.c`、`servo.h`

避免使用 `test1.c`、`new2.c`、`最终版.c` 等无法表达用途的名称。

## 提交信息示例

- `feat: 添加舵机角度控制接口`
- `fix: 修复 PWM 周期计算错误`
- `docs: 登记 Timer2 和舵机引脚`
- `test: 增加单舵机异常角度测试`

请勿提交密码、Token、Wi-Fi 密码等敏感信息。
